## 1. 이슈 개요

- 대상 이슈: [#4 디자인 시스템 설계 및 목업 UI 구현](https://github.com/sunnypark87/AI-Builder-Sprint-Loop/issues/4)
- 우선순위: P0
- 상태: Open
- 담당자: sunnypark87
- 작성일: 2026-07-30

모두싸인 웹 서비스의 정보 구조와 UI/UX 패턴을 참고해 프로젝트 전용 디자인 시스템을 정의하고, 공통 레이아웃과 재사용 가능한 컴포넌트로 메인, AI 계약서 작성, 계약서 관리, 기부 내역 조회, 기부처 분석 목업 페이지를 구현한다. 실제 SaaS처럼 일관되고 자연스러운 시각 품질과 기본 반응형 동작을 달성하되 실제 API, 백엔드, 실데이터 연동은 포함하지 않는다.

## 3. 선행 결정

- 모두싸인의 상표·카피·자산을 복제하지 않고 정보 구조, 밀도, 계층, 폼 패턴을 참고해 프로젝트 고유 디자인으로 재해석한다.
- Tailwind CSS 4와 React를 기본으로 사용하며, shadcn/ui 등 새 컴포넌트 의존성은 접근성 또는 구현 비용상 명확한 이점이 있을 때만 추가한다.
- 제품명은 `모두기브(modugive)`로 확정했다. 기부처에는 기부 집행 관리, 기부자에는 집행 확인을 제공해 신뢰도 높은 기부처와 기부의 선순환을 만드는 흐름을 기준으로 한다.
- 브랜드 강조색은 `#fb4d00`으로 확정했다. 접근성 대비를 위해 기본 CTA에는 `#212121` 전경을 사용하고 흰색 전경이 필요할 때는 `#c83d00` 배경을 사용한다.
- Modal은 정적 예시에 그치지 않고 열기·닫기, 포커스 이동, Escape 닫기, 배경 포커스 차단을 포함한 최소 접근성 동작까지 구현한다.
- 모두싸인 레퍼런스 분석과 토큰 사용 규칙은 `docs/design-system.md`를 기준 문서로 관리한다.

## 4. 구현 단계

### 단계 1. 레퍼런스 분석과 디자인 기반 정의

#### 작업 내용

- 모두싸인의 레이아웃, 내비게이션, 정보 계층, 폼, 목록, 상태 표현을 분석하고 프로젝트에 적용할 원칙과 적용하지 않을 요소를 정리한다.
- 중립색·브랜드색·상태색, 타이포그래피 계층, 간격, 반경, 그림자, 포커스 링을 CSS 변수와 Tailwind theme token으로 정의한다.
- 모바일·태블릿·데스크톱 중단점과 콘텐츠 최대 너비, 그리드 규칙을 문서화한다.

#### 완료 조건

- [x] 디자인 레퍼런스와 프로젝트 스타일 원칙이 문서화되어 있다.
- [x] Color, Typography, Spacing을 포함한 디자인 토큰이 한 곳에서 관리된다.
- [x] 토큰이 명도 대비, 포커스 가시성, 반응형 레이아웃 기준을 포함한다.

### 단계 2. 공통 컴포넌트와 앱 셸 구현

#### 작업 내용

- Button, Input, Card, Dialog와 단계·상태·안내 컴포넌트의 공통 props, variant, 크기, 비활성·오류·포커스 상태를 설계하고 구현한다.
- Header, Sidebar, Navigation과 모바일 내비게이션을 포함한 앱 셸을 구현한다.
- 활성 메뉴, 페이지 제목, 주요 행동 영역을 라우트별 설정으로 재사용할 수 있게 구성한다.

#### 완료 조건

- [x] 공통 컴포넌트가 중복 마크업 없이 여러 화면에서 재사용된다.
- [x] 키보드 포커스, 레이블, 의미 있는 HTML 등 기본 접근성을 충족한다.
- [x] 앱 셸이 주요 중단점에서 콘텐츠를 가리지 않고 자연스럽게 재배치된다.

### 단계 3. 주요 목업 페이지 구현

#### 작업 내용

- 메인 화면에 핵심 현황, 빠른 작업, 최근 계약 또는 기부 요약을 구성한다.
- AI 계약서 작성 화면에 단계 또는 섹션 기반 입력 폼과 생성 전 안내 상태를 구성한다.
- 계약서 관리 화면에 검색·필터·상태 표시가 포함된 목록 또는 테이블을 구성한다.
- 기부 내역 조회 화면에 요약 지표, 기간 필터, 내역 목록을 구성한다.
- 기부처 분석 화면에 신뢰도 요약, 평가 근거, 주의 요소를 과장 없이 구분해 표현한다.
- 모든 데이터는 명시적인 정적 목업 fixture로 분리하고 실제 데이터처럼 오인되지 않도록 한다.

#### 완료 조건

- [x] 요구된 5개 목업 페이지가 고유 URL로 접근 가능하다.
- [x] 모든 페이지가 동일한 앱 셸, 토큰, 공통 컴포넌트를 사용한다.
- [x] 모바일, 태블릿, 데스크톱에서 핵심 콘텐츠와 행동이 사용 가능하다.
- [x] 실제 API 또는 백엔드 없이 정적 목업 데이터만으로 렌더링된다.

### 단계 4. 품질 검토와 문서 갱신

#### 작업 내용

- 과도한 그라데이션, 비현실적인 카드 남용, 장식적 애니메이션 등 Issue에서 지양한 패턴을 점검한다.
- 화면 간 간격, 컬러, 타이포그래피, 상태 표현과 컴포넌트 재사용성을 검토한다.
- AGENTS.md와 README에 추가된 주요 디렉터리 책임, 페이지 경로, 실행·검증 방법을 필요한 범위에서 반영한다.

#### 완료 조건

- [x] 팀 디자인 리뷰에서 실제 SaaS 수준의 일관성과 자연스러움을 확인한다.
- [x] 공통 컴포넌트로 대체 가능한 중복 스타일과 마크업이 남아 있지 않다.
- [x] 저장소 구조와 실행 방법 문서가 실제 구현과 일치한다.

AI 동작 변경 여부는 `해당 없음`이다. 이번 Issue는 AI 계약서 작성 화면의 정적 목업만 다루며 모델 호출, 프롬프트, AI 출력 처리 로직을 추가하지 않는다. 따라서 AI 정확성·프롬프트 인젝션 검증은 제외하되, 신뢰도와 AI 생성 결과처럼 보이는 목업 문구가 사실 또는 실제 분석 결과로 오인되지 않는지는 수동 검토한다.

### 변경 내용

- 논리 중심 UI 원칙과 AI 템플릿 안티패턴을 디자인 시스템에 추가했다.
- 홈의 설명 카드, 상담 발화 카드, 등록 단계 카드, 대시보드 지표 카드와 결제수단 카드를 여백·구분선·목록 중심 구조로 개선했다.
- 페이지 헤더의 반복적인 `예시 데이터` 강조를 업무 맥락으로 교체하고 semantic color token과 motion token을 보강했다.
- 전체 목업을 재검토해 목록·설정 화면의 불필요한 카드를 추가로 제거하고, 문자 아이콘을 Lucide 아이콘으로 통일했으며, 끊어진 `/account` 흐름에 데모 역할 선택 화면을 추가했다.
- 파트너 관리 목록을 화면별 컬럼, 로컬 상태 탭, 결과 건수와 빈 상태를 지원하도록 확장하고 대시보드 업무 건수를 필터된 목록에 연결했다.
- 계획·증빙·보고서 검토 화면에 원본과 AI 결과 비교 영역을 추가하고 공개·발행·기부처 서명 전 영향 범위를 확인하는 Dialog를 적용했다.
- 단계·상태·분류·경고를 하나의 둥근 Badge로 표현하던 구조를 `FlowProgress`, `StatusIndicator`, `InlineNotice`, `FilterTabs`로 분리하고 페이지의 Badge 사용을 제거했다.
- 기부처 등록을 정보 입력과 맞춤 약정서 작성의 2단계로 구체화하고, PDF 1–2페이지를 참고한 표준 입력·개인정보 조항과 기부처별 집행 공개·중단·잔액·추가 조항 편집 및 실시간 미리보기를 구현했다. PDF 3페이지의 현물 기부용 장부가액 확인서는 제외했다.

### AI 정확성 및 안전성 검증

- AI 동작 변경 여부: 없음. diff에 프롬프트, 모델 호출, 검색, 추출 로직, AI Route 또는 모델 출력 처리 코드가 없다.
- 정확성 검증 결과: 해당 없음. AI 분석·상담·보고 문구는 정적 목업이며 데모·예시·담당자 검토 필요 문구가 표시된 것을 확인했다.
- 안전성 검증 결과: 실제 결제가 발생하지 않고 금융정보를 입력·저장하지 않는다는 안내와 개인정보 검토 문구를 확인했다. 실데이터·비밀정보 패턴은 발견되지 않았다.
- AI가 발견하거나 예방한 품질 문제: 목업 AI 결과가 실제 결과로 오인되지 않도록 예시·데모·검토 필요 표현과 원본 비교 구조가 포함된 것을 확인했다.
- 최종 판정: PASS

### 차단 항목과 미검증 범위

- 차단 항목 없음.
- 브랜드 아이콘 도형은 사용자 결정에 따라 유지하고 파일명과 참조를 `modugive_logo.svg`로 변경했다.
- Playwright 스크린샷은 검증용 임시 산출물로 `/tmp/modugive-responsive`에 생성하며 저장소에는 포함하지 않는다.
- 미검증: GitHub API 연결 실패로 원격 Issue 본문을 직접 재확인하지 못했다. 브랜치명과 로컬 계획 문서로 Issue #4 범위를 식별했다.
- 미검증: npm registry DNS 연결 실패로 의존성 보안 권고를 재조회하지 못했다. 로컬 정적 검사와 전체 품질 게이트는 통과했다.

### 남은 작업과 알려진 제한

- 실제 백엔드·AI·결제 연동은 이번 정적 목업 범위에 포함하지 않는다.
- 브라우저 E2E는 로컬 Chromium 설치가 필요하며 `npx playwright install chromium` 후 실행한다.
