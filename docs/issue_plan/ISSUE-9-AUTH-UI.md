# Issue 구현 계획

## 1. 이슈 개요

- 대상 이슈: [#9 로그인·회원가입 UI 구현 및 Supabase Auth 연동](https://github.com/sunnypark87/AI-Builder-Sprint-Loop/issues/9)
- 우선순위: P0
- 상태: Open
- 담당자: sunnypark87
- 작성일: 2026-07-31

Supabase Auth 이메일 인증을 실제 사용자 화면에 연결한다. 로그인·회원가입·로그아웃, 유효성 검사와 사용자 친화적 오류 처리, 세션 유지, 인증 상태별 헤더를 구현하여 기부자가 안전하고 일관되게 인증 흐름을 사용할 수 있게 한다.

## 2. 현재 저장소 상태

관련 코드, 문서, 설정, 테스트의 현재 상태를 조사해 기록한다.

| 요구사항             | 현재 상태                                                              | 필요한 작업                                                                                      |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 로그인·회원가입 화면 | 제품용 Auth 화면은 없고 `/dev/auth-test`에 로그인 smoke test만 존재    | 디자인 시스템을 따르는 제품용 로그인·회원가입 라우트와 반응형 폼 구현                            |

| 회원가입·로그인 연동 | 개발용 화면에서 `signInWithPassword`만 직접 호출                       | `signUp`, `signInWithPassword`를 재사용 가능한 Auth 흐름으로 분리하고 성공 후 안전한 경로로 이동 |
| 로그아웃             | 개발용 화면에서만 `signOut` 호출                                       | 제품 헤더에서 로그아웃을 제공하고 세션·화면·라우터 상태 갱신                                     |
| 인증 오류·로딩       | 개발용 일반 메시지와 `isBusy`만 존재                                   | Supabase 내부 오류를 노출하지 않는 사용자 메시지, 중복 제출 방지, 안정적인 로딩 상태 구현        |
| 세션 유지            | `proxy.ts`와 `updateSession`, 브라우저 세션 helper가 구현·테스트됨     | 기존 쿠키 갱신 기반을 유지하며 로그인·새로고침·로그아웃 제품 흐름에서 통합 검증                  |
| 보호 라우트          | 이번 이슈 범위에서 제외                                                | 별도 이슈에서 서버 검증 기반 보호 라우트 구현                                                    |
| 인증 상태별 Header   | `DonorHeader`가 항상 `로그인` 링크를 표시                              | 서버에서 전달하거나 안전하게 초기화한 인증 상태에 따라 로그인 또는 사용자·로그아웃 UI 표시       |
| 테스트               | Supabase helper와 Proxy 단위 테스트는 있으나 제품 Auth 폼 테스트 없음  | SDK mock 기반 정상·오류·경계 컴포넌트 테스트와 Header 테스트 추가                                |

## 3. 선행 결정

- 제품 Auth 경로는 `/login`과 `/signup`을 기본안으로 사용하고, 기존 `/account`는 데모 역할 선택 화면이므로 로그인 화면으로 재사용하지 않는다.
- 보호 라우트는 이번 이슈 범위에서 제외하고 별도 이슈로 분리한다.
- Proxy는 세션 쿠키 갱신만 담당하게 유지하고, 접근 제어는 Server Component 또는 서버 전용 helper에서 `getCurrentUser()`로 수행한다.
- 로그인 후 이동 경로는 검증된 내부 상대 경로만 허용하고 기본값은 `/`로 한다. 외부 URL이나 스킴을 허용하지 않아 오픈 리다이렉트를 방지한다.
- 회원가입 후 이메일 확인이 활성화된 환경에서는 즉시 로그인된 것으로 가정하지 않고 확인 안내를 표시한다. 이메일 확인이 비활성화되어 세션이 반환되면 로그인 성공과 같은 방식으로 처리한다.
- Supabase 원문 오류, 토큰, 세션, 사용자 식별자를 UI·로그에 노출하지 않고 오류 유형을 제한된 한국어 메시지로 매핑한다.
- 별도 폼 라이브러리나 스키마 검증 의존성을 우선 추가하지 않고 현재 React·TypeScript와 공유 UI로 구현한다.

## 4. 구현 단계

### 단계 1. Auth 도메인 동작과 검증 규칙 구성

#### 작업 내용

- 이메일, 비밀번호, 비밀번호 확인의 클라이언트 검증 규칙과 오류 메시지를 정의한다.
- 로그인, 회원가입, 로그아웃 호출과 Supabase 오류 메시지 변환을 제품 코드로 분리한다.
- 로그인 후 이동 경로를 내부 경로로 제한하고 회원가입 결과의 세션 유무를 구분한다.

#### 완료 조건

- [ ] 빈 값·잘못된 이메일·비밀번호 정책 불충족·비밀번호 불일치가 제출 전에 필드별로 안내됨
- [ ] 로그인·회원가입·로그아웃의 정상·실패 결과가 안전한 제품 상태로 변환됨
- [ ] Supabase 내부 오류와 민감정보가 사용자 메시지나 로그에 노출되지 않음
- [ ] 외부 URL을 로그인 후 이동 대상으로 사용할 수 없음

### 단계 2. 로그인·회원가입 UI 구현

#### 작업 내용

- `/login`, `/signup` 페이지와 재사용 가능한 Auth 폼 컴포넌트를 구성한다.
- 공유 `Input`, `Button`, `InlineNotice`와 디자인 토큰을 사용해 필드 오류, 제출 로딩, 성공·실패 안내를 구현한다.
- 로그인과 회원가입 사이의 이동, 접근 가능한 레이블·포커스, 360px 이상 반응형 레이아웃을 제공한다.

#### 완료 조건

- [ ] 로그인·회원가입 화면이 디자인 시스템과 한 화면 한 기본 CTA 원칙을 준수함
- [ ] 제출 중 버튼 크기가 유지되고 중복 제출이 차단됨
- [ ] 오류 원인과 해결 방법이 관련 필드 또는 폼 가까이에 표시됨
- [ ] 키보드, 스크린 리더 레이블, 200% 확대와 모바일 너비에서 핵심 흐름을 사용할 수 있음

### 단계 3. 인증 상태·헤더·로그아웃 연결

#### 작업 내용

- 초기 인증 상태와 Auth 변경 이벤트를 일관되게 반영하는 UI 경계를 구성한다.
- `DonorHeader`의 데스크톱·모바일 UI를 비로그인 시 로그인, 로그인 시 사용자 상태와 로그아웃 동작으로 전환한다.
- 로그아웃 성공 시 캐시된 서버 화면을 갱신하고 공개 기본 경로로 이동하며, 실패 시 복구 가능한 메시지를 표시한다.

#### 완료 조건

- [ ] 로그인 직후와 새로고침 후 Header가 로그인 상태를 정확히 표시함
- [ ] 로그아웃 성공 후 세션과 로그인 전용 UI가 제거됨
- [ ] 로그아웃 실패 시 로그인 상태를 오인하지 않고 재시도 안내가 제공됨
- [ ] 데스크톱·모바일 Header가 동일한 Auth 상태와 기능을 제공함

### 단계 4. 실제 환경 검증과 문서화

#### 작업 내용

- 로컬 테스트 계정으로 회원가입·로그인·새로고침·라우트 이동·로그아웃 흐름을 수동 검증한다.
- 모바일·데스크톱 뷰포트와 키보드 사용성을 확인하고 `npm run check`, `verify-change` 결과를 실행 결과에 기록한다.

#### 완료 조건

- [ ] 실제 Auth 계정으로 핵심 로그인 흐름이 확인됨

### 단계 5. 자동 테스트와 실제 환경 검증

#### 작업 내용

- Supabase SDK와 네트워크를 mock하여 로그인, 회원가입, 로그아웃, 오류 매핑, Header 테스트를 추가한다.
- 로컬 테스트 계정으로 회원가입·로그인·새로고침·라우트 이동·로그아웃 흐름을 수동 검증한다.
- 모바일·데스크톱 뷰포트와 키보드 사용성을 확인하고 `npm run check`, `verify-change` 결과를 실행 결과에 기록한다.

#### 완료 조건

- [ ] 정상·오류·경계 Auth 흐름의 자동 테스트가 실제 외부 키 없이 통과함
- [ ] 로컬 제품 흐름과 세션 유지 수동 검증 결과가 기록됨
- [ ] 반응형·접근성 수동 검증 결과가 기록됨
